# Технический аудит и исправления — 2026-10-17

## Подтверждённые проблемы в предоставленном архиве

1. Запросы `/api/auth` и `/api/me` в frontend использовали `fetch` без тайм-аута. Если WebView или сервер не завершал запрос, начальная заставка могла оставаться на экране неопределённо долго.
2. Не было аварийного завершения заставки с понятным сообщением и возможностью повторить запуск.
3. Комментарии были плоскими: схема и API не имели `parent_id`, UI не позволял отвечать.
4. Список комментариев загружался без общей функции с обработкой сетевых ошибок и без явной защиты от повторной отправки комментария.

## Исправления в этом наборе

- Авторизация и получение профиля используют общий helper с AbortController и ограничением времени.
- Добавлен fail-safe начальной загрузки с кнопкой повтора.
- В `comments` добавлено nullable-поле `parent_id` с внешним ключом на `comments(id)` и `ON DELETE CASCADE`; миграция выполняется безопасно через `ADD COLUMN IF NOT EXISTS`.
- API комментариев возвращает `parent_id`, проверяет существование видео и принадлежность родительского комментария тому же видео.
- Ответы и обычные комментарии сохраняются в той же таблице; `comments_count` пересчитывается из реальных строк внутри транзакции.
- UI показывает ветки ответов, позволяет выбрать адресата ответа, отменить ответ и отправить его. Отправка блокируется на время запроса.
- Удаление родительского комментария каскадно удаляет его ответы; интерфейс предупреждает об этом.

## Ограничения проверки

- Статические регрессионные тесты, Python-компиляция и проверка синтаксиса встроенного JavaScript выполняются локально.
- Реальная база Supabase, Telegram WebView, Railway и Android-устройство в этой среде не подключены. Интеграционные и визуальные проверки необходимо выполнить после развёртывания.
- Наличие обложки в плитках зависит от фактического `thumbnail_url`; генерация превью из видеопотока этим изменением не добавлена.
