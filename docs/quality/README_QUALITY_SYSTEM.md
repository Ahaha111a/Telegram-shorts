# Telegram Shorts — система качества

Основные документы этого проекта хранятся именно в `docs/quality/`. Они описывают требования, дизайн, проверку регрессий и историю дефектов. Документы не заменяют реальные тесты приложения.

## Файлы
- `PROJECT_RULES.md` — порядок разработки, безопасность и правила выдачи файлов.
- `REQUIREMENTS.md` — подтверждённые продуктовые требования и критерии приёмки.
- `DESIGN_SYSTEM.md` — дизайн и UX.
- `QA_CHECKLIST.md` — ручные и статические проверки.
- `BUG_LEDGER.md` — причины, статусы и профилактика дефектов.

## Ограничения
- GitHub Actions и платная инфраструктура не используются без отдельного согласия пользователя.
- Статические проверки не доказывают корректность поведения в Telegram WebView, Railway или Supabase.
- Статус `PASS` ставится только при фактической проверке; непроведённые проверки помечаются `BLOCKED` или `NOT RUN`.
