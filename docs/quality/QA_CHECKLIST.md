# Telegram Shorts — чек-лист качества и регрессий

Отмечать результат как `PASS`, `FAIL`, `BLOCKED` или `NOT RUN`. Не отмечать PASS без фактической проверки.

## A. Статика и структура
- [ ] `bot.py` компилируется без синтаксических ошибок.
- [ ] `requirements.txt` и `dist/index.html` существуют.
- [ ] HTML разбирается без ошибок парсинга.
- [ ] Нет повторяющихся HTML ID.
- [ ] Просмотрен diff и изменены только ожидаемые файлы.

## B. Загрузка и запуск
- [ ] Mini App открывается в Telegram WebView.
- [ ] Загрузка завершается; при ошибке есть понятное состояние.
- [ ] Нет бесконечного спиннера или ложного пустого состояния.
- [ ] Повторное открытие после закрытия работает.

## C. Лента
- [ ] Свайпы переключают ролики.
- [ ] Активный ролик играет; неактивный не играет незаметно.
- [ ] Лайк не меняет состояние воспроизведения.
- [ ] Username, описание и хэштеги не выходят за границы.
- [ ] «Для тебя»/«Подписки» переключаются плавно.
- [ ] Нижняя навигационная панель полностью отсутствует; место под неё не зарезервировано.
- [ ] Нет серой рамки вокруг username.
- [ ] Кнопки действий не имеют лишних подписей.

## D. Навигация
- [ ] Каждый оставшийся видимый элемент ведёт на правильный экран.
- [ ] Нет мёртвых кнопок и пустых переходов.
- [ ] Закрытие/возврат работает корректно.
- [ ] Камера не добавлена.
- [ ] История просмотров полностью отсутствует.

## E. Профиль и социальные функции
- [ ] Аватар, имя, username и био отображаются корректно.
- [ ] Счётчики и подписи выровнены.
- [ ] Сохранённый ролик открывает правильное видео.
- [ ] Удаление доступно только владельцу.
- [ ] Комментарии отправляются без дубликатов и панель закрывается по ожидаемому сценарию.
- [ ] Жалоба «Другое» требует причину и показывает результат.

## F. Публикация
- [ ] Видео загружается; сетевые ошибки обрабатываются.
- [ ] Описание и хэштеги сохраняются и видны после повторного открытия.
- [ ] Обязательные данные валидируются.
- [ ] Результат загрузки понятен.

## G. Адаптивность
- [ ] Проверен узкий Android-экран.
- [ ] Длинные имена и описания не перекрывают кнопки.
- [ ] Области касания достаточно велики.
- [ ] Клавиатура и безопасные области не закрывают критические действия.
- [ ] Загрузка, ошибки, пустые данные и повторные нажатия обработаны.

## H. Перед выпуском
- [ ] Все доступные статические проверки пройдены.
- [ ] Применимые ручные проверки выполнены либо помечены BLOCKED с объяснением.
- [ ] `REQUIREMENTS.md` и `BUG_LEDGER.md` обновлены.
- [ ] Отчёт отделяет проверенное от непроверенного.

Примечание: GitHub Actions в текущем процессе не используется. Этот чек-лист — рабочий документ, а не утверждение об автоматическом запуске проверок.
