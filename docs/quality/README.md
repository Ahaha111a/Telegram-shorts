# Telegram Shorts — система качества

Эта папка — обязательный регламент разработки и выпуска. Перед каждой значимой задачей изучай `PROJECT_CONTEXT.md`, `PRODUCT_SPEC.md`, `ARCHITECTURE.md` и `BUG_PREVENTION.md`; после изменений обновляй `CHANGELOG.md` и выполняй `TESTING.md`.

## Порядок работы
1. Сверить ZIP с `main` по Git blob SHA.
2. Зафиксировать первопричину и затронутые пользовательские сценарии.
3. Вносить минимальный согласованный набор изменений.
4. Запустить доступные автоматические проверки и отдельно записать то, что не проверялось на устройстве/production.
5. Проверить структуру архива и отсутствие секретов.
6. Не считать задачу закрытой без регрессионных проверок.

## Документы
- `PROJECT_CONTEXT.md` — подтверждённая архитектура и ограничения.
- `PRODUCT_SPEC.md` — продуктовые сценарии и требования.
- `UI_UX_STANDARDS.md` — правила интерфейса и safe areas.
- `ARCHITECTURE.md` — потоки данных, API и слои.
- `TESTING.md` — обязательные тесты.
- `BUG_PREVENTION.md` — причины известных классов ошибок и профилактика.
- `RELEASE_CHECKLIST.md` — выпуск.
- `CHANGELOG.md` — история конкретных изменений.
- `TASK_WORKFLOW.md` — рабочий процесс.
- `AUDIT_REPORT.md` — текущий аудит с пометками подтверждённости.

Сведения о production-переменных и внешних настройках не считаются проверенными, пока это не подтверждено доступом к соответствующей системе.
