# Аудит Telegram Shorts — 2026-10-11 (v16)

## Изменения в этом архиве
- Убраны возможные фоновые слои/псевдоэлементы поверх видео и тени/фон у `.meta`; `.video-gradient` и `.slide-top-safe` принудительно прозрачны. Если тёмная область остаётся, требуется проверить исходный MP4: затемнение может быть частью самого видео, а не CSS. Это нельзя доказать только по скриншоту.
- Кнопка с тремя точками на карточке видео в профиле теперь открывает общее меню действий (`openMoreMenu`), а не сразу диалог удаления.
- Улучшены оформление сетки профиля, кнопок меню и статистики.
- Для сетки видео включена загрузка метаданных, чтобы браузер мог декодировать первый кадр, если у видео нет `thumbnail_url`. Это временный fallback; правильное решение — генерировать и сохранять thumbnail при загрузке.
- Сохранены исходные файлы и структура проекта.

## Важные ограничения, которые нельзя честно считать решёнными кодом интерфейса
1. **Telegram deep links:** `https://t.me/<bot>?startapp=video_<id>` открывает Mini App только если Main Mini App корректно настроен в BotFather. Если приложение настроено как отдельное именованное Web App, ссылка должна включать его short name: `https://t.me/<bot>/<short_name>?startapp=video_<id>`. Имя приложения неизвестно из репозитория, поэтому оно не выдумывалось. Проверить настройку BotFather и переменную `WEB_APP_URL` после deploy.
2. **Превью старых видео:** backend хранит `thumbnail_url`, но не гарантирует наличие миниатюры у каждого уже загруженного ролика. Нужна серверная генерация кадра (например, FFmpeg) с безопасным fallback.
3. **Полноэкранный свайп:** браузерный scroll-snap сам по себе не гарантирует TikTok-поведение на каждом Android WebView. Требуется ручной тест: один короткий свайп — ровно один следующий/предыдущий ролик, без двойного перелистывания; повторить в ленте, профиле и сохранённых.
4. **Производительность:** включение metadata для плиток помогает превью, но может увеличить сетевые запросы в больших профилях. Следующий шаг — lazy observer, генерация thumbnails и тестирование с 50+ видео.
5. **Безопасность/данные:** отдельно протестировать авторизацию initData, права удаления, ограничения размера/типа загрузки, rate limiting, приватность жалоб и согласованность лайков/счётчиков.

## Приоритетный QA-план
- P0: проверить отсутствие CSS-градиента на последних 25% экрана; открыть исходный MP4 вне приложения и сравнить яркость низа.
- P0: проверить share link на телефоне с установленным Telegram, с Main Mini App настроенным и без него.
- P0: по одному свайпу в обе стороны на feed/profile/saved/search; быстро повторить 10 раз.
- P1: профайл grid — миниатюра до открытия, быстрый скролл, повторное открытие просмотрщика.
- P1: три точки на своём видео — сначала меню; удаление только после выбора «Удалить» и подтверждения.
- P1: сетевой режим медленный/обрыв; повторная попытка без зависания и без бесконечного loading.
- P2: 50+ роликов, устройство с малой памятью, уход в фон/возврат, ориентация и safe areas.
